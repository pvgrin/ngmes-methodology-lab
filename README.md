# NGMES Methodology Lab

Лаборатория методологии поставки ценности в управлении производством:
от наблюдаемой проблемы через проверяемое решение к подтверждённому результату.
Единый продукт развивается в сторону MES/NGMES — управления производственными
операциями. Методология объясняет выбор, границы и проверку каждого шага;
AI-SDLC организует разработку. Rust используется для предметного ядра.

Текущий пример — качество партии и реакция ответственного. Он разделяет
измерение, получение данных, человеческое решение и сохраняемую историю.
Это учебный прототип. Производственное применение и эффект ещё не проверены.

**Версия 0.3.0-internal.1 принята владельцем 29.10.2026; публикация разрешена.**
Суффикс версии сохранён для точного соответствия принятому коду. Здесь
поставляются исходники, синтетические примеры и проверки. Код, документы
и примеры — [Apache-2.0](LICENSE), Copyright 2026 Pavel Grinevich;

## Сборка и проверка

Проверенная среда — macOS ARM64, уже установленный Rust 1.98.0 и Python 3.9+
с `sqlite3` и `fcntl`. Компилятор использует системный инструментарий сборки.
Загрузка зависимостей и автоматическая установка не предусмотрены.
Из корня репозитория:

```sh
python3 -I checks/verify.py --integrity-only
RUSTFLAGS="--remap-path-prefix=$(pwd)=/nml-build/product" cargo build --locked --offline --release
python3 -I checks/verify.py
```

Проверяющий использует только этот каталог и установленный инструментарий.
Он подаёт входы последовательно, проверяет 25 срезов, историю, разные процессы
при восстановлении, повторную доставку и неверные команды. JSON в конце
содержит фактический результат; ненулевой код означает ошибку.
[Свидетельство текущей поставки](evidence/public-verification-0.3.0-internal.1.json)
отделено от исторических проверок версии 0.2.

Обычный запуск наследует права пользователя. Проверяющий ограничивает время
и завершает свои процессы, но сам не создаёт песочницу. Для недоверенных
изменений требуется отдельно подготовленная изолированная среда.

## Посмотреть третий шаг

```sh
python3 -I nml01.py --binary target/release/nml01-core < inputs/C04.jsonl
```

Отбор в 09:00, срок 09:45, измерение 09:30 пришло в 09:50: показатель 15 мг/л
соответствует. Ожидание закрыто, но задержка и открытое рассмотрение сохранены.
Для решения и перезапуска используйте новый каталог:

```sh
mkdir nml-late-state
python3 -I nml01.py --binary target/release/nml01-core --store nml-late-state/flow.sqlite < inputs/C04-FLOW-start.jsonl
python3 -I nml01.py --binary target/release/nml01-core --store nml-late-state/flow.sqlite < inputs/C04-FLOW-resume.jsonl
python3 -I nml01.py --binary target/release/nml01-core --store nml-late-state/flow.sqlite --history
```

Первый процесс сохраняет отказ руководителю и `check` ответственного с
основанием. Новый процесс восстанавливает решение; повтор увеличивает
доставки до двух, сохраняя один результат, один вопрос и одно принятое решение.
Для повторения нужен новый каталог. Без `--store` история живёт в памяти,
`storage_acknowledged` равно `false`.

Прежние C01, C02, C03, C10 и C12 остаются в `inputs/` и проверяются вновь.
Роли учебные, без удостоверения личности. Программа не разрешает отгрузку.
Первый результат ровно на сроке пока отклоняется. Миграции баз 0.2 нет:
новой версии нужен новый файл; старую историю читает прежний бинарник.
Исправления, конфликты и производственные интеграции остаются открытыми задачами.
