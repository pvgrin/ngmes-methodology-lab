# NGMES Methodology Lab

Лаборатория методологии поставки ценности в управлении производством:
от наблюдаемой проблемы через проверяемое решение к подтверждённому результату.
Здесь методология сопровождается небольшими исполняемыми примерами на Rust,
контрольными ожиданиями и свидетельствами проверки.

Первый пример — качество партии и реакция ответственного. Он показывает,
как разделять качество измерения, получение данных, человеческое решение
и сохранность истории. Это учебный прототип, а не промышленная MES
(система управления производственными операциями).

## Сборка и проверка

Проверенная среда — macOS ARM64, уже установленный Rust 1.98.0 и Python 3.9
с модулями `sqlite3` и `fcntl`. Компилятор использует системный инструментарий
сборки. Автоматическая установка и загрузка зависимостей не предусмотрены.
Команды выполняются из корня этого каталога:

```sh
python3 -I checks/verify.py --integrity-only
RUSTFLAGS="--remap-path-prefix=$(pwd)=/nml-build/product" cargo build --locked --offline --release
python3 -I checks/verify.py
```

Проверка использует только содержимое этого каталога и установленный
инструментарий. Она запускает реальные процессы, создаёт временные SQLite-файлы,
проверяет 14 срезов, историю, восстановление, повторную доставку и неверные
команды. В конце печатает JSON с объёмом и результатом; ненулевой код означает
ошибку. Входы подаются по одному, после ответа на предыдущий.

Обычный запуск наследует права пользователя. Скрипт проверки ограничивает
время и завершает собственную группу процессов, но не создаёт изолированную
песочницу. Для недоверенных изменений нужна отдельно подготовленная среда.

## Попробовать пример

```sh
python3 -I nml01.py --binary target/release/nml01-core < inputs/C01.jsonl
python3 -I nml01.py --binary target/release/nml01-core < inputs/C02.jsonl
```

Первая команда показывает соответствие при 15 мг/л. Вторая — отклонение
при 21 мг/л, его проверку и передачу вопроса. Решение не меняет качество
на «соответствует» и не разрешает отгрузку. Без `--store` история живёт только
в памяти: `storage_mode: "memory"`, `storage_acknowledged: false`.

Для восстановления создайте отдельный новый рабочий каталог:

```sh
mkdir nml-demo-state
python3 -I nml01.py --binary target/release/nml01-core --store nml-demo-state/c12.sqlite < inputs/C12-start.jsonl
python3 -I nml01.py --binary target/release/nml01-core --store nml-demo-state/c12.sqlite < inputs/C12-resume.jsonl
python3 -I nml01.py --binary target/release/nml01-core --store nml-demo-state/c12.sqlite --history
```

После первой команды процесс завершён. Новый процесс восстанавливает решение
D-1; повтор E-1 увеличивает доставки до двух, оставляя один результат и одно
решение. Для повторения возьмите новый каталог: повторная регистрация в старой
истории запрещена. Перед продолжением используйте тот же бинарник, иначе
проверка его хеша отклонит историю. Файл `.lock` обслуживает блокировку;
не удаляйте его во время работы.

JSON содержит один объект на строку; поля показаны в примерах. Дополнительные
команды: `status` (последнее подтверждённое состояние), `read_report` (чтение),
`decision` (решение). Даты UTC; единица `mg/L` (мг/л), значения целые.
Неправильный вход даёт код 2. Корректная попытка запрещённого по роли решения
записывается с `last_decision_accepted: false`; код 0 подтверждает запись
отказа, а не принятие решения.

Методология и демонстрация разрабатываются совместно. AI-SDLC используется
для постановки, исполнения и проверки работы; этот каталог является
самостоятельным результатом и не требует внутренней инфраструктуры разработки.
